## Kannu 1.3.0 — Heimdall

Kannu watches your AI coding agents from the MacBook notch. This release adds a second thing worth
watching: whether those agents are doing anything you would not want them to.

Requires macOS 14.6 or later. Existing installs update in place.

---

### Agent Security — a new tab

Agents read files, run commands and talk to MCP servers on your behalf. Kannu now watches that
surface and collects what it finds in one place: **Settings › Agent Security**.

- **Kannu's own checks** run inside the agent hook, in real time, with no model and no network:
  - **Secrets** that appear in a prompt or in what an agent passes to a tool. Kannu records the
    kind, the prefix and a short fingerprint — never the key itself.
  - **Sensitive files** an agent reads or writes: SSH keys, cloud and git credentials, keychains,
    password stores, browser data, `.env` files, shell startup files, agent configs.
  - **Hidden text** — characters that are invisible on screen but readable by the model, the
    technique behind "ASCII smuggling" prompt injection. Kannu catches Unicode tag blocks,
    variation-selector runs, bidirectional overrides and long zero-width runs.
  - **New MCP servers** appearing in an AI tool's settings, since a new server runs with that
    tool's access.
  - **Sessions running with permission checks off**, which can change files and run commands
    without asking.
- **An agent policy you can enforce.** Write rules — by command or by tool name — in
  `~/.kannu/agent-policy.json`, or have your agent draft them for you, or edit them from inside
  Kannu. Report-only by default: a match is recorded and the call still runs. Turn on **Block
  matching tool calls** and Claude Code and Cursor will refuse the call and tell the agent why;
  every other agent still gets the finding.
- **ADR Discovery**, Uber's open-source agent-discovery toolkit, if you install it yourself. Kannu
  finds it, runs it on a cadence and reads the results: unpinned MCP servers, servers reached over
  plain HTTP, servers running that nothing declared. Kannu never installs it for you.
- **Session analysis** with ADR Detection is entirely opt-in, per run, behind a consent sheet — it
  is the only feature that sends a transcript anywhere.

A high-severity finding shows a shield beside the traffic light and stays until you acknowledge it.
Everything else lives in Settings. Kannu never edits your configs and never stops a process.

### The notch gets out of the way

- **On a notched MacBook, the closed notch no longer swallows clicks.** Kannu's window spans a
  strip wider than the notch itself; it now hit-tests only the notch shape, so a click on the menu
  bar beside it — or on a browser tab under it — reaches what you aimed at.
- **One Kannu, on the display you are using.** The three overlapping display settings are replaced
  by a single choice. By default the external display takes over when one is connected, and the
  built-in notch is used when it is not. With two or more externals, Kannu follows your pointer.

---

### It stops costing you battery

Three measured passes over the hot paths. Numbers are before and after, on the same Mac:

| While | CPU | Idle wakeups |
|---|---|---|
| An agent is working (steady traffic light) | **53.1 % → 0.9 %** | **13,356/s → 12/s** |
| An agent fires hook events in bursts | **18.2 % → 3.7 %** average (79 % → 13.9 % peak) | — |

The traffic light now animates on Core Animation instead of re-running a SwiftUI animation every
frame; timers behind it are gone, replaced by single wakes at the moment something expires. The
closed notch also stopped re-rendering its whole view on every agent event — under a busy Claude
Code session that alone had been averaging 38 % CPU.

### When something goes wrong, you can say so

- **Crash reports.** If Kannu quit unexpectedly, the next launch offers to report it. It builds a
  prefilled GitHub issue you read and submit yourself — with your username, machine identifiers and
  volume names stripped out. Kannu sends nothing on its own.
- **Freezes too.** A watchdog notices when the app stops responding, records where it was stuck,
  and offers the same report on the next launch.
- **Two freezes fixed at the source:** Settings file pickers no longer run a nested modal loop that
  could wedge the app, and connecting AirPods no longer blocks the main thread on a subprocess.

---

### Settings, rebuilt

Every tab now follows macOS System Settings: one label column, one control column, descriptions
under titles instead of tooltips. Spacing, indentation, type sizes and slider widths come from a
single set of tokens, so sections line up with each other. Any explanatory text can be selected and
copied. The Agents tab split in two — behaviour stays in **Agents**, everything security-related
moved to **Agent Security**.

---

### Watching more agents, and more closely

- **New agents:** GitHub Copilot CLI, Gemini CLI, Qwen Code and opencode join Claude Code, Cursor,
  Codex, VS Code and Antigravity. Warp and Claude Desktop's agent mode are read passively.
- **Each chat shows what this request cost:** how long it has been running, how many tool calls it
  has made, and tokens in and out.
- **Clicking a chat lands where it is:** the exact Terminal or iTerm2 tab, the exact tmux pane, or
  the exact conversation inside Claude Desktop — not just the app.
- **Usage limits** get a forecast, so you can see a limit coming instead of hitting it, with an
  optional alert.
- **One card per chat.** A Claude Code chat that spawns subagents shows as one chat, not several
  untitled ones. A finished chat stays listed for a moment instead of vanishing, and its card says
  if the request ended on an error.
- **The menu bar icon is Kannu's eye.** Clicking it opens the notch on whichever display your
  pointer is on; right-click still gives you the menu.

### What changes when you update

Two things are deliberately different after this update, and you may want to set them back:

- **Your display choice is reset.** The old "show on all displays" and "switch display
  automatically" settings were replaced by a single setting with no migration path, so everyone
  starts on the new default — the external display takes over. If you had Kannu on every display,
  choose **All displays** in Settings › General.
- **Kannu's own security checks are on.** Findings will start appearing in Settings › Agent
  Security, and a high-severity one shows a shield in the notch until you acknowledge it. All of it
  runs on this Mac: nothing is uploaded, no AI model is involved, and secrets are recorded as a
  fingerprint rather than a value. Each check has its own switch if you would rather not.

Blocking is **not** switched on for you — the agent policy starts in report-only mode, and an empty
policy blocks nothing.

### Also fixed

- A chat no longer lights up as "thinking" because you typed or pasted a draft into its chat bar
  without sending it.
- A Cursor chat driven by an embedded Claude Code engine stops flapping between the two labels.
- The notch stopped crashing in a layout loop with SwiftUI over its own window size.
- A chat left waiting on a permission prompt stays yellow while the prompt is genuinely open,
  instead of going dark after five minutes.
- Security and usage-limit notifications arrive once, on time, and never carry the chat's name.
- A leftover now-playing helper process no longer outlives the app that spawned it.
- The documented clone-and-build instructions work again, and the README no longer tells you to
  strip quarantine from an app that is properly notarized.
