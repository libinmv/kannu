## Kannu 1.3.2 — Heimdall

A battery fix, and it is the important kind: 1.3.1 introduced a loop that made Kannu re-draw itself
continuously, whatever you had switched on or off. If Kannu has felt hot or thirsty since 1.3.1,
this is why. It also fixes five older leaks that a settings toggle left running behind it.

Requires macOS 14.6 or later (unchanged since 1.2.0). Existing installs update in place.

---

### The drain 1.3.1 introduced

Security findings are rebuilt from scratch every time Kannu publishes them, and a single equality
check — "is this the same list as last time?" — is what stops that rebuild from waking the notch, the
closed pill and Settings. 1.3.1's grouping work stamped the *rebuild's* clock into each finding, so
no two rebuilds were ever equal, the check never held, and everything re-rendered on every pass.

Measured on a machine with findings present, against a steady state documented at 0.9% CPU and 12
idle wakeups a second: **33.9% CPU and 172 wakeups/s**, rising to **41.2% and 928/s** thirty seconds
later, with no agent running and nothing in the logs. Activity Monitor weights wakeups heavily, which
is how that reads as an Energy Impact in the thousands.

A finding's "last seen" is now a real timestamp that does not move unless the thing itself moved — the
scan's own time for a Discovery finding, the session's own last event for an unattended one. A test
now pins the rule the whole mechanism rests on: rebuilding from unchanged input produces an identical
list, even at a different time of day.

### Five things a settings toggle used to leave running

Reported as "after continuously toggling all different types of settings… tried disabling all
different features; uses half battery in about 20 minutes". Turning features off did not help because
none of this belonged to a feature:

- **Changing the Music Source left the old controller running.** Switching away from Amazon Music
  left its helper process streaming to nobody — one more every time, outliving Kannu itself.
  Switching away from YouTube Music left a two-second poll and a connection that kept
  *re-establishing itself* indefinitely. Both now shut down when they are replaced, and the code will
  no longer compile if a new one forgets to.
- **Opening the HUD & OSD settings started a display poll that nothing stopped.** Even with every HUD
  feature switched off, looking at that pane began reading the display 6.7 times a second for the
  rest of the session — and switching the feature off again could not stop it, because it was already
  off. The preview no longer starts anything.
- **Toggling the real-time waveform added two permanent system observers each time**, which then
  fired on every music app you opened, for the rest of the session.
- **Switching Focus detection modes queued up a day of log reading**, once per switch, with nothing
  cancelling the previous one — so it kept reading long after you had switched back.
- **Three places left a pipe handler installed after the process behind it exited**, which makes the
  system wake Kannu over and over to read nothing.

### A grouped finding says which chats it came from

1.3.1 started showing one row per problem instead of one per sighting, so a rule that fired in three
chats became a single row. The row said *how many* occurrences but not *where*, and you had to expand
it to find out. It now reads:

> **Policy matched "ssh" — it ran**
> 7 occurrences · 3 chats · first 17 Sep at 15:49 · last 25 Sep at 16:41
> Tenant Delete Agent, gitlab orchestration, +1

Two chats that happen to share a title now count as two rather than collapsing into one.

### Those lines are readable now

The recurrence line, the chat list, the acknowledgement note and the breakdown were rendered in a
component built for a trailing file path: one line, shortened *in the middle*. That is right for
`/Users/…/snapshot.json` and wrong for a sentence, which appeared with its middle cut out. They wrap.
