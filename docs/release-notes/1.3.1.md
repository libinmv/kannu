## Kannu 1.3.1 — Heimdall

A fix for a bug that could make Kannu look like it had stopped working, and a change to security
findings so you acknowledge a problem once instead of every time it comes back.

Requires macOS 14.6 or later. Existing installs update in place.

---

### The notch could go blank

On 1.3.0, Kannu could end up drawing nothing at all — no island, no traffic light, and hovering the
notch did nothing either — while the app itself was running perfectly normally. It happened after an
ordinary lock or display sleep, and once it started it did not recover on its own.

Two things caused it, and both are fixed:

- Kannu decides whether to hide the closed notch by asking which display it is on. If it had not
  worked that out yet — a launch while the screen was locked, in clamshell, or with every display
  asleep — it treated "I don't know" as "hide", permanently. It now shows the notch unless something
  is genuinely fullscreen.
- The same unknown display also collapsed the notch to zero height, which removed the hover target,
  so you could not point at it to bring it back. An unresolved display now keeps its height.

Two smaller repairs came with it. **Granting Accessibility matters more than it looks:** without it
Kannu could not tell a fullscreen window from a merely maximised one, and it used to guess
"fullscreen" — which hid the notch for any maximised window on a fresh install, because installing a
new build resets that permission. It no longer guesses, and says so in the log. And when macOS drops
the "screen unlocked" notification — which it does — Kannu now recovers its windows from its own
check rather than waiting for you to plug in a display.

---

### Security findings: one row per problem

If the same problem kept happening, Kannu kept asking you to acknowledge it again. On one Mac that
meant **28 acknowledgements for 3 actual problems**.

The worst case was a rotating credential. AWS temporary keys are re-issued constantly, and Kannu
identified each one separately — so a single "this chat keeps putting a key into a Bash command"
became 21 findings, and would have kept growing forever. The same `ssh` rule firing in three
different chats was three more.

Findings are now grouped by the *problem*, with the parts that churn left out of its identity. Each
row tells you what you asked for:

> **The agent used a secret in a tool call** · 22 occurrences · first 25 Sep at 12:57 · last 25 Sep
> at 17:56

Expanding a row shows what was folded together — how many separate sightings, which projects, how
many chats — so nothing is hidden by the grouping. For a rotating key that count is the number that
matters: 21 distinct keys, not 21 rows.

**Acknowledging now settles the problem.** It stays quiet however often it recurs, and comes back
only if it gets worse: the severity rises, or the outcome changes — a command that used to just run
is now being blocked, or the reverse.

**And you choose how far it reaches.** The button reads "Acknowledge for kannu-site" and applies to
the project it happened in, because deciding a command is fine in one repo says nothing about
another. "Acknowledge everywhere" is in the "…" menu. If a problem spans a project you acknowledged
and one you have not, the row stays and says *"Still open in kannu"* rather than quietly hiding.

The notch shield, its pill and the optional push all count problems now too, so one recurring issue
is one alert rather than twenty-one.

**Nothing you have already acknowledged comes back.** Existing acknowledgements are carried over.
